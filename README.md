# FantasyBoard

A fantasy football draft board: consensus expert rankings merged with live ADP, dragged into
your own custom order, with tiers, favorites, notes, and live pick tracking — usable instantly
as a guest, or signed in with Google to sync boards across devices.

**Live:** [fantasydraftboard.vercel.app](https://fantasydraftboard.vercel.app)

## Features

- **Consensus rankings + live ADP** — FantasyPros ECR, ESPN's analyst-blended ranks, FFC
  (FantasyFootballCalculator) ADP, and Sleeper roster/bye-week data merged into one PPR and one
  standard ranking bundle per player, with a week-over-week ADP delta (▲ rising / ▼ falling).
- **Drag-and-drop custom order** — reorder the full player pool (1,000+ players) into your own
  board. The list is virtualized (only rows near the viewport are ever mounted) so dragging stays
  smooth at full scale.
- **Custom tiers** — drop a tier break in anywhere via the "+" gap between any two ranks. A tier
  is anchored to the player below it, so it moves with that player if they're reordered, rather
  than needing to be dragged itself.
- **Search while editing** — searching no longer disables itself in edit mode; it scrolls to and
  highlights the match instead, since filtering the list while editing would desync drag
  adjacency from the real saved order.
- **Draft tracking** — mark a player drafted by you or an opponent, undo a pick, hide drafted
  players, reset the whole draft.
- **Favorites & notes** — star targets and leave a note on any player, saved on the board.
- **Guest or signed-in boards** — guest boards persist to `localStorage` with no account needed;
  signing in with Google creates named boards synced in real time to Firestore across devices.
- **PPR / Standard**, plus position filters including FLEX.

## Tech stack

- **Next.js 16** (App Router), **React 19**, **TypeScript**, **Tailwind CSS v4**
- **@dnd-kit** for drag-and-drop, **@tanstack/react-virtual** for list virtualization
- **Zustand** (`persist` middleware) for guest boards; **Firebase Auth + Firestore** for
  signed-in, cross-device boards
- **Zod** for schema validation in the rankings pipeline
- Deployed on **Vercel**

## Architecture

```
app/            App Router pages — / (landing), /guest, /boards (dashboard),
                /boards/[boardId] (a signed-in board), /privacy
components/     UI: PlayerTable/PlayerRow/TierRow (the virtualized draft board),
                FilterBar, BoardShell (logic shared between guest & signed-in),
                GuestBoard / FirestoreBoardView (data-source-specific wrappers),
                PlayerDetailModal, and smaller presentational pieces
lib/            store.ts (Zustand guest store), firestoreBoards.ts (Firestore-backed
                board hooks/actions), boardOps.ts (pure ops shared by both stores),
                derive.ts (row/tier derivation, filtering, sorting), auth.tsx
                (Google sign-in), types.ts, normalize.ts
data/           Generated players.json (current) + players-week-ago.json (rolling
                snapshot used for the ADP delta) + seed/ (curated expert consensus
                rankings + name aliases)
scripts/        fetch-rankings.ts — the rankings/ADP fetch-and-merge pipeline
```

`BoardShell` holds all the shared board logic (filters, sort, tiers, edit modes); `GuestBoard`
and `FirestoreBoardView` each wire it up to a different persistence layer (Zustand+localStorage
vs. Firestore) so the board UI itself doesn't need to know which one it's running against.

## Getting started

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Guest mode works immediately with no
configuration — boards persist to `localStorage`.

### Optional: Firebase (sign in to sync boards across devices)

```bash
cp .env.local.example .env.local
# fill in NEXT_PUBLIC_FIREBASE_* from your Firebase project's web app config
```

Without this, "sign in with Google" is unavailable, but guest boards work fully either way.

## Refreshing rankings / ADP

Player data lives in `data/players.json`, generated by merging:

- `data/seed/expert-rankings.json` — a curated expert consensus ranking (seed order).
- Live rankings/ADP from FantasyPros, ESPN's public fantasy API, FantasyFootballCalculator, and
  Sleeper (rosters, bye weeks).

To regenerate it (e.g. for a new season, or to pick up ranking/ADP movement):

```bash
npm run fetch:rankings -- --season=2026
```

The script validates ESPN analyst-rank coverage against a minimum threshold and prints a
match-rate summary. If a seed name fails to match a live-source player (nicknames, suffixes,
etc.), add an entry to `data/seed/name-aliases.json` mapping the seed name to that source's name
and re-run.

To update the underlying expert consensus order itself, edit `data/seed/expert-rankings.json`
directly, then re-run the fetch script.
